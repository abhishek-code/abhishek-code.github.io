Troubleshooting Agent Behavior in Agentforce

A practical, step-by-step diagnostic guide for testing, fixing configuration & data, resolving routing & acting errors, grounding limits, and handling runtime integration issues.

2. Test Scenario Baseline: Customer Service Refund Action

Throughout this troubleshooting guide, we follow a concrete, real-world customer service scenario:

Scenario: Duplicate Charge Refund

User Request: "I was charged twice for order #ORD-99182. Please process a refund of $49.99 back to my credit card."

Expected Outcome: The agent routes to the Order_Management topic, extracts Order_Number and Amount, calls the Process_Customer_Refund action, and returns a transaction confirmation.

3. Step-by-Step Diagnostic Framework

  • 1

    Getting Started: Observability and Trace Logging Setup

    Before analyzing behavior, establish an isolated testing environment and activate full execution trace logging in Agent Builder.

    • Launch Agent Builder Debugger: Open Agent Builder and toggle the Trace Canvas sidebar.
    • Enable Extended Logging: Ensure Event Monitoring logging is enabled for Agentforce events (AgentforceExecutionLog).
    • Simulate User Context: Set up test records for Contact, Account, and Order ORD-99182 to populate session parameters.
  • 2

    Fixing Configuration and Data Issues

    Validate that the Agent Definition metadata is properly constructed and that essential CRM records exist and are visible to the agent's execution context.

    Common Failures: Missing record IDs in test context, inactive Agent assignment, or missing object access.

    Example: Data Access & User Context Check

    Verify that the Agentforce Context User profile or permission set contains appropriate object-level access:

    SOQL Verification Query:
SELECT Id, Status__c, TotalAmount__c, AccountId 
FROM Order 
WHERE OrderNumber = 'ORD-99182'

    If the query returns no records when executed under the Agent Context User, the action cannot inspect or refund the order due to record-level sharing or FLS restrictions.

  • 3

    Resolving Routing, Acting, and Prompting Issues

    If the agent selects the wrong topic, skips an action, or responds unpredictably, the issue typically stems from ambiguous natural language descriptions or missing action constraints.

    A. Topic Routing Misclassification

    Agents classify user intent against Topic Descriptions. If two topic descriptions overlap, routing fails.

    Example: Fixing Topic Routing Descriptions

    Ambiguous Description (Causes Failure):

    Handles general questions and customer support regarding orders.

    Remediated Description (Clear Scope & Boundaries):

    Handles explicit order processing actions including issuing refunds, processing duplicate payment corrections, canceling items, and adjusting billing discrepancies for existing orders.

    B. Action Parameter Extraction (Acting & Prompting)

    When the topic is correct but the agent fails to run the action, review parameter descriptions and instructions.

    Example: Action Input Parameter Definition
    Action: Process_Customer_Refund
Parameter Name: Order_Identifier
Description: The alphanumeric order code starting with 'ORD-' extracted from the user query.
Requirement: Required before executing the refund flow.
  • 4

    Troubleshooting Grounding, Limits, and Common Errors

    Ensure that knowledge context, Data Cloud RAG queries, and token limits do not corrupt the reasoning process.

    A. Grounding & RAG Retrieval Failures

    If the agent fabricates policies or reports missing knowledge, inspect the underlying Vector Search configuration and search filters.

    Example: Knowledge Grounding Diagnostic

    Check if the Refund Policy article is published and indexed in Data Cloud Vector Database:

    Status: Published
Searchable Scope: Service Knowledge Index
Filter Constraint: Category = 'Billing_and_Refunds'

    B. Token Limits & Guardrail Errors

    When prompts exceed token windows or trigger safety rules, the Einstein Trust Layer suppresses execution.

    • Toxicity & PII Masking: Review if masking rules replace valid IDs (e.g., masking credit card numbers or order codes as [REDACTED_NUMBER]).
    • Loop Detection: If an action calls itself repeatedly, lower the maximum plan iteration threshold.
  • 5

    Resolving Runtime and Integration Issues

    Runtime errors occur during Flow invocation, Apex class execution, or external REST API endpoint calls.

    Example: Debugging Invocable Apex / Flow Errors

    If the trace log displays EXCEEDED_MAX_ELEMENTS or INVOCATION_EXCEPTION, check the underlying Flow logic:

    Error Trace:
[Action: Process_Customer_Refund] -> Flow Exception: 
System.LimitException: Too many SOQL queries: 101

Remediation:
Bulkify the Apex controller backing the Invocable Method or ensure the Flow does not query inside a loop.

4. Troubleshooting Diagnostic Reference Matrix

Category Observed Behavior Root Cause Resolution
Configuration & Data Agent says "I don't have access to that information." Context User lacks FLS/CRUD or sharing rights. Assign required Permission Set to Agent Context User.
Routing Agent routes refund query to FAQ topic. Topic description is too broad or ambiguous. Add specific keywords and scope boundaries to Topic Description.
Acting Agent asks user for details already provided. Parameter description lacks extraction context. Update action input description to explicitly specify formatting.
Grounding Agent hallucinates non-existent refund timelines. RAG index missing or out-of-date article. Re-index Knowledge Articles in Data Cloud search index.
Runtime Trace shows Flow failure or timeout. Flow error or external API integration timeout. Inspect Debug Logs in Setup -> Debug Logs for the Agent User.
