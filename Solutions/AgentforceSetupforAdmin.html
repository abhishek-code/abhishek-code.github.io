Agentforce Setup for Admins

1. Solution Overview 2. Solution Description 3. High-Level Architecture 4. 5-Minute Implementation 5. Metadata & Deployment

1. What the Solution Does

Operationalizing Agentforce Setup and Administrative Governance

The Agentforce Setup solution enables Salesforce Administrators to configure, license, and deploy autonomous AI agents across the Enterprise. It establishes the organizational foundation by enabling Einstein and Agentforce capabilities, provisioning user access permissions, configuring agent topics and actions, and establishing Einstein Trust Layer guardrails directly within the Salesforce CRM setup environment.

2. Solution Description

The Problem: Organizations face complexity when configuring autonomous AI agents without a unified administrative roadmap. Unregulated AI rollouts create security risks around data exposure, lack granular access controls, and result in inconsistent agent execution across core sales and service processes.

The Solution: A structured administrative deployment in Salesforce Setup. Administrators activate Agentforce features, assign dedicated Permission Sets and License assignments, assign grounded Agent Actions (Flows, Apex, Prompt Templates), and enforce strict data masking and safety protocols using the Einstein Trust Layer.

3. High-Level Architecture

The solution relies on four key components of the Salesforce ecosystem working seamlessly together:

Salesforce Setup Einstein & Agentforce Core Activation
→
Access & Governance Permission Sets, Licenses & Security Profiles
↓
Deployment Endpoints Lightning Pages, Experience Cloud & Messaging
←
Agent Builder Topics, Instructions & Action Assignment
←
Einstein Trust Layer Data Masking, Safety & Guardrails
  • Salesforce Setup: Controls global organization settings, enabling Einstein, Agentforce, and underlying Data Cloud integrations.
  • Access & Governance: Enforces granular user and system access using explicit Agentforce user permissions, licenses, and object-level security.
  • Agent Builder & Trust Layer: Serves as the configuration studio where administrators assign topics, ground agent actions, and apply data privacy and toxic-content filters.
  • Deployment Endpoints: Surfacing activated autonomous agents directly into Lightning App Builder, Experience Cloud sites, or messaging channels.

4. Implementation Steps (5-Minute Summary)

You can build this solution in these four sequential stages:

  • Step 1: Enable Einstein and Agentforce (~1 min)
    Navigate to Salesforce Setup, search for Einstein Setup, and toggle Einstein on. Locate Agentforce Setup and turn on Agentforce to unlock agent configuration capabilities.
  • Step 2: Assign Licenses & Permission Sets (~1 min)
    Assign the Agentforce User/Admin Permission Set Licenses to designated administrative and target user profiles. Create and assign permission sets granting access to specific agent actions and objects.
  • Step 3: Configure Agent Topics, Actions & Guardrails (~1.5 min)
    Open Agent Builder. Select or create an Agent, define system instructions, and add Topics. Attach grounded Actions (Flows, Apex classes, or Prompt Templates) to each topic, and verify data masking in the Einstein Trust Layer settings.
  • Step 4: Activate & Deploy Agent to Endpoints (~1.5 min)
    Test the agent within the Agent Builder preview panel. Once validated, activate the Agent. Embed the agent component into target Lightning Record Pages, Utility Bars, or digital channels using Lightning App Builder.

Consultant Takeaway

Administrative setup for Agentforce requires zero code. By establishing foundational security, licensing, and grounded Agent Actions within Salesforce Setup, administrators can deploy trusted autonomous capabilities across any CRM channel efficiently.

Meta-data for Git Repository

To move the solution built in a sandbox through a CI/CD pipeline and extract it to a Git repository, you need to grab the metadata components for agent definitions, permission sets, actions, and page layouts.

Use at least API Version 60.0 or higher in your sfdx-project.json or package.xml manifest, as Agentforce metadata types require modern API versions.

The precise metadata types you can extract using the Salesforce CLI (sf project retrieve) are organized by architectural layer below:

1. The Agentforce & AI Configuration Layer

These components contain agent definitions, topics, actions, and prompt templates:

  • Bot: Represents the Agent definition created within Agent Builder.
  • BotVersion: Stores specific configuration versions, topics, and system instructions for the agent.
  • GenAiPlugin: Defines custom actions and topic plugins attached to the Agentforce agent.
  • GenAiPromptTemplate: Houses the grounded prompt templates assigned as agent actions.

2. The Governance & Security Layer

These elements handle permissions, licenses, and access controls:

  • PermissionSet: Controls access to specific Agentforce features, flows, apex actions, and field permissions.
  • CustomPermission: Custom permissions created to gate agent action visibility and execution.

3. The UI & Channel Deployment Layer

These elements define where the agent surfaces in core CRM:

  • FlexiPage: Lightning pages configured with the Agentforce component.
  • CustomApplication: Utility bar definitions containing the Agentforce messaging component.

Example package.xml Manifest

Create a package.xml file using the snippet below to extract the complete end-to-end solution directly into your local Git tracking folder:

<?xml version="1.0" encoding="UTF-8"?>
<Package xmlns="http://soap.sforce.com/2006/04/metadata">
    <!-- Agentforce Agent & Topic Metadata -->
    <types>
        <members>*</members>
        <name>Bot</name>
    </types>
    <types>
        <members>*</members>
        <name>BotVersion</name>
    </types>
    <types>
        <members>*</members>
        <name>GenAiPlugin</name>
    </types>
    <types>
        <members>*</members>
        <name>GenAiPromptTemplate</name>
    </types>

    <!-- Governance & Security -->
    <types>
        <members>Agentforce_Admin_Access</members>
        <members>Agentforce_User_Access</members>
        <name>PermissionSet</name>
    </types>

    <!-- UI Deployment & Experience -->
    <types>
        <members>Service_Console_UtilityBar</members>
        <name>CustomApplication</name>
    </types>
    <types>
        <members>Case_Record_Page</members>
        <name>FlexiPage</name>
    </types>
    <version>65.0</version>
</Package>

Consultant Sandbox Exception

Global Einstein Setup toggles and tenant-level Agentforce activation settings cannot be deployed via Metadata API. You must manually turn on Einstein and Agentforce in Setup within target environments prior to retrieving or deploying package metadata.
