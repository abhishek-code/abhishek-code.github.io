Loyalty Management & Data Cloud 360

1. Solution Overview 2. Solution Description 3. High-Level Architecture 4. 5-Minute Implementation 5. Metadata & Deployment

1. What the Solution Does

Integrating Salesforce Loyalty Management with Data 360 for Unified Member Profiles and Actionable Segmentation

This solution establishes a bidirectional synchronization pattern between Salesforce Loyalty Management and Salesforce Data Cloud. It ingests member program details, point ledgers, tier changes, and promotion engagements into Data Cloud to harmonize loyalty records with cross-channel behavior. The resulting insights enable dynamic segment generation, targeted promotion triggers, and personalized engagement across operational channels.

2. Solution Description

The Problem: Loyalty member data often resides in isolated program tables separate from broader transactional, web, and service activity. Without unified data streaming, enterprises struggle to recalculate member tiers dynamically, deliver timely promotion offers, or surface up-to-date points balances across external touchpoints.

The Solution: Leveraging native Data Cloud ingest connectors for Loyalty Management objects (such as Loyalty Program Member, Member Tier, and Loyalty Ledger), organizations convert operational records into Data Lake Objects (DLOs) and standard Data Model Objects (DMOs). Data Cloud calculated insights run real-time metrics across member behaviors, driving automated segments and orchestrating personalized member journeys via Flow and Data Actions.

3. High-Level Architecture

The solution relies on four key components of the Salesforce ecosystem working seamlessly together:

Loyalty Management Program Members, Tiers & Ledgers
→
Data Cloud Ingestion CRM Bundles & Data Streams (DLOs)
↓
Activation & Actions Segments, Data Actions & Flow Triggers
←
Calculated Insights Tier Aggregations & Engagement Metrics
←
Identity & Mapping Unified Member DMOs & Match Rules
  • Loyalty Management: Functions as the core operational engine capturing program enrollment, transaction ledgers, member tiers, and rewards.
  • Data Cloud Ingestion & Mapping: Ingests loyalty entities via native Salesforce CRM Connectors into DLOs, mapping them to standard Data Cloud Data Model Objects (DMOs).
  • Identity Resolution & Insights: Resolves member identities across disparate touchpoints and executes Calculated Insights to compute lifetime value, point balances, and engagement frequency.
  • Activation & Execution: Streams unified member segments to Marketing Cloud, Service Cloud, or triggers automated Salesforce Flows via Data Actions upon tier changes.

4. Implementation Steps (5-Minute Summary)

You can build this solution in these four sequential stages:

  • Step 1: Connect Loyalty Data Streams (~1 min)
    In Data Cloud Setup, launch the Salesforce CRM Connector and deploy the standard Loyalty Management data bundle. Ingest core objects including LoyaltyProgramMember, LoyaltyMemberTier, and LoyaltyLedger into Data Lake Objects (DLOs).
  • Step 2: Map to Standard DMOs & Configure Identity Resolution (~1 min)
    Map DLO attributes to target Data Model Objects (Individual, Account, and Loyalty DMOs). Configure Identity Resolution rulesets combining Contact Point Email and Member ID to produce a single Unified Profile.
  • Step 3: Define Calculated Insights (~1.5 min)
    Build SQL-based or visual Calculated Insights in Data Cloud to compute rolling 90-day engagement metrics, active point balances, and tier upgrade eligibility thresholds per unified member.
  • Step 4: Create Segments & Configure Data Actions (~1.5 min)
    Publish target member segments based on calculated insight outputs. Configure Data Actions to push activation targets to Marketing Cloud or trigger Flow orchestrations for personalized outreach.

Consultant Takeaway

By leveraging standard CRM Data Bundles for Loyalty Management, integration requires minimal custom ETL work. Data Cloud unifies operational loyalty records with external behavioral data, making dynamic tier calculations and targeted rewards available out-of-the-box.

Meta-data for Git Repository

To move the solution built in a sandbox through a CI/CD pipeline and extract it to a Git repository, you need to grab the metadata components for data stream definitions, insight models, segments, and flow orchestrations.

Use at least API Version 60.0 or higher in your sfdx-project.json or package.xml manifest to support Data Cloud and Loyalty metadata types.

The precise metadata types you can extract using the Salesforce CLI (sf project retrieve) are organized by architectural layer below:

1. The Data Cloud Ingestion & Mapping Layer

These components control data streams, field maps, and calculated insights:

  • DataStreamDefinition: Defines the source ingestion configurations connecting Loyalty Management to DLOs.
  • DataSrcDataModelFieldMap: Contains field mapping configurations connecting Loyalty DLOs to standard DMOs.
  • MarketSegmentDefinition: Metadata definitions for segments built on unified loyalty member profiles.

2. The Automation & Platform Layer

These elements handle business logic and workflow triggers across core CRM:

  • Flow: Process automation triggered by Data Actions upon loyalty segment membership or tier updates.
  • CustomField: Custom attributes added to standard Loyalty objects to capture unified insight values.
  • PermissionSet: Access controls governing Data Cloud and Loyalty Management object visibility.

Example package.xml Manifest

Create a package.xml file using the snippet below to extract the complete end-to-end solution directly into your local Git tracking folder:

<?xml version="1.0" encoding="UTF-8"?>
<Package xmlns="http://soap.sforce.com/2006/04/metadata">
    <!-- Data Cloud Ingestion & Mapping -->
    <types>
        <members>*</members>
        <name>DataStreamDefinition</name>
    </types>
    <types>
        <members>*</members>
        <name>DataSrcDataModelFieldMap</name>
    </types>
    <types>
        <members>*</members>
        <name>MarketSegmentDefinition</name>
    </types>

    <!-- Automation & Governance -->
    <types>
        <members>Loyalty_Tier_Notification_Flow</members>
        <name>Flow</name>
    </types>
    <types>
        <members>Loyalty_DataCloud_Integration_Admin</members>
        <name>PermissionSet</name>
    </types>
    <version>65.0</version>
</Package>

Consultant Sandbox Exception

Identity Resolution rulesets and active data streams must be validated manually post-deployment in target orgs. Ensure that both Salesforce Data Cloud and Loyalty Management licenses are active and connected prior to package deployment.
