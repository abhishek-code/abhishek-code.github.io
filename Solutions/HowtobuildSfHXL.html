1. What the Solution Does

Delivering Rich Agentic UI and Headless Interactive Experiences via Custom Lightning Types, Components, Widgets, and Supported Channels

The Salesforce Headless Experience Layer (HXL) extends agentic capabilities beyond plain text conversations. By decoupling raw server execution from display rendering, HXL uses Custom Lightning Types, Components, and HXL Declarative Widgets to deliver rich, interactive user experiences. A single Apex action payload or Model Context Protocol (MCP) tool response can render native LWC components inside Salesforce apps and declarative HXL Widgets on external surfaces such as ChatGPT, Claude, Slack, or embedded web applications.

2. HXL Core Architecture & Artifacts

Building rich UI experiences in Salesforce Headless requires understanding how data shapes bind to input and output renderers across different surfaces:

  • Custom Lightning Type (LightningTypeBundle): The metadata bundle that defines data validation schema (schema.json), mapping Apex structures or object shapes to UI configurations.
  • Components (In-App Channels): Code-based custom UI (HTML, JS, CSS) used for collecting structured input (editor.json) or displaying rich output (renderer.json) within internal Salesforce applications.
  • HXL Widgets (UiWidgetBundle): Declarative, JSON-composed UI components that use an attribute contract (schema.json). Rendered through root-level renderer.json files, widgets enable consistent UI across both native Salesforce surfaces and external MCP host applications (e.g., ChatGPT, Claude).
  • Supported Channels & Surfaces: Specific interaction environments (e.g., Agentforce Desktop, Mobile, Experience Builder, or MCP clients) that consume the rendered outputs.

4. Step-by-Step Implementation: Flight Reservation Custom UI

Scenario: Build a custom Salesforce headless solution for a "Flight Booking & Seat Selection" workflow. The agent collects filter options using a custom form component and renders interactive flight cards across multiple display channels.

Step 1: Define the Apex Payload Data Model (~1.5 min)

Create an Apex class with @AuraEnabled fields that define the structured data payload returned by the business process:

public with sharing class FlightSearchResult {
    @AuraEnabled public String flightNumber;
    @AuraEnabled public String airline;
    @AuraEnabled public String departureAirport;
    @AuraEnabled public String arrivalAirport;
    @AuraEnabled public Decimal price;
    @AuraEnabled public String departureTime;

    @InvocableMethod(label='Search Flights' description='Returns structured flight results for HXL UI rendering')
    public static List<FlightSearchResult> searchFlights(List<String> destinationCodes) {
        List<FlightSearchResult> results = new List<FlightSearchResult>();
        FlightSearchResult res = new FlightSearchResult();
        res.flightNumber = 'SF-101';
        res.airline = 'Salesforce Air';
        res.departureAirport = 'SFO';
        res.arrivalAirport = destinationCodes.isEmpty() ? 'JFK' : destinationCodes[0];
        res.price = 350.00;
        res.departureTime = '08:00 AM';
        results.add(res);
        return results;
    }
}

Step 2: Create the Custom Lightning Type Bundle (~2 min)

In your Salesforce DX project under force-app/main/default/lightningTypes/flightResult, create the required schema.json file referencing the Apex class:

{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "Flight Search Result",
  "type": "object",
  "lightning:type": "@apexClassType/FlightSearchResult",
  "properties": {
    "flightNumber": { "type": "string" },
    "airline": { "type": "string" },
    "price": { "type": "number" },
    "departureTime": { "type": "string" }
  }
}

Step 3: Configure Channel-Specific LWC UI Overrides (~2 min)

To render a custom LWC inside Agentforce for Lightning Desktop, place renderer.json inside the channel subfolder lightningDesktopGenAi:

/* File: lightningTypes/flightResult/lightningDesktopGenAi/renderer.json */
{
  "component": "c:flightResultCard",
  "attributes": {
    "flightNumber": "{!$attrs.flightNumber}",
    "airline": "{!$attrs.airline}",
    "price": "{!$attrs.price}",
    "departureTime": "{!$attrs.departureTime}"
  }
}

Step 4: Configure Cross-Platform HXL Widget Override (~2 min)

To support third-party surfaces like ChatGPT or Slack via MCP, define a root-level renderer.json (parallel to schema.json) that maps custom type properties to an HXL Widget bundle:

/* File: lightningTypes/flightResult/renderer.json */
{
  "componentOverrides": {
    "widget": {
      "name": "c:flightCardWidget",
      "attributes": {
        "title": "{!$attrs.airline}",
        "subtitle": "{!$attrs.flightNumber}",
        "badgeText": "{!$attrs.departureTime}",
        "priceValue": "{!$attrs.price}"
      }
    }
  }
}

Step 5: Define the HXL Declarative Widget Bundle (~2 min)

Create the HXL Widget bundle in force-app/main/default/uiwidgets/flightCardWidget using a schema.json attribute contract and a composition definition:

/* File: uiwidgets/flightCardWidget/schema.json */
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "title": { "type": "string" },
    "subtitle": { "type": "string" },
    "badgeText": { "type": "string" },
    "priceValue": { "type": "number" }
  }
}

5. Supported Channels and Application Overrides

HXL handles UI rendering differently depending on whether the target platform is an internal Salesforce application or an external partner channel:

🏢 Native Salesforce Applications (LWC Overrides)

Uses channel-specific subfolders inside LightningTypeBundle. Supports both input forms (editor.json) and output cards (renderer.json).

  • lightningDesktopGenAi: Agentforce Employee Agent in Lightning Desktop.
  • enhancedWebChat: Agentforce Service Agent via Enhanced Chat v2.
  • lightningMobileGenAi: Agentforce on Mobile (iOS & Android).
  • experienceBuilder: Experience Cloud sites.

🌐 Headless Third-Party Channels (HXL Widgets)

Uses root-level renderer.json without channel subfolders. Uses JSON-based declarative composition for output rendering across MCP hosts.

  • ChatGPT / OpenAI MCP Client: Interactive card rendering via MCP server tools.
  • Claude / Anthropic MCP Client: Structured visual widget payloads.
  • Slackbot / Slack Apps: Interactive Block Kit/HXL widget execution.

6. Governance & Key Takeaways

Adhering to correct project structure and governance standards ensures seamless deployment and lifecycle management for Headless Experience Layer implementations:

Deployment & Governance Rules

  1. Deploy via Salesforce CLI & Metadata API: Do not create or edit widget-backed Custom Lightning Types manually in Setup. Define and deploy them via source control using LightningTypeBundle and UiWidgetBundle metadata types.
  2. Maintain Attribute Contracts: Always include a valid schema.json file in widget bundles to enable compile-time data validation and attribute mapping.
  3. Strict Separation of Rendering Files: Keep Component overrides isolated in channel subfolders (e.g., lightningDesktopGenAi/renderer.json) while placing HXL Widget mappings at the root level.

Architectural Summary

By pairing Custom Lightning Types with Components and HXL Widgets for external MCP platforms, enterprises can deliver a unified, high-fidelity user interface across every AI channel—without duplicating business logic or backend code.
