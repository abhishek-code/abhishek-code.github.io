Advanced RAG: Data Cloud & Agentforce

1. Solution Overview 2. Solution Description 3. High-Level Architecture 4. 5-Minute Implementation 5. Metadata & Deployment

1. Solution Overview

When Agents are grounded in data from Data 360, they access a vast knowledge base of up-to-date, unified customer data.

This solution extends Salesforce AI past basic record grounding and into true semantic search using Data 360 (Data Cloud). Grounded Agents build responses dynamically based on real customer experiences instead of static, generic text properties.

In this architecture, we implement an autonomous service agent grounded in Case data. The RAG pipeline parses unstructured text fields (Subject and Description) to securely isolate contextual answers.

2. Solution Description

The Problem: Large Language Models (LLMs) are powerful but prone to hallucination. Standard Salesforce CRM text search falls short when dealing with deep unstructured data repositories (like thousands of PDFs, knowledge articles, or raw text logs) because it fails to grasp semantic context or semantic intent.

The RAG Solution Matrix
By combining Data 360 (Data Cloud) and Agentforce, you ingest unstructured assets, transform text into mathematical vector embeddings, and store them natively. Custom retrievers let autonomous Agentforce Service Agents tap into these secure data silos seamlessly.

3. High-Level Solution Architecture

The technical transaction relies on a deep real-time orchestration between Salesforce Data Cloud and the Einstein AI platform layer:

[ Unstructured Data Sources ] │ (PDFs, Knowledge, External Docs) ▼ ┌────────────────────────────────────────────────────────┐ │ DATA 360 (DATA CLOUD) │ │ 1. Vector Search Index (Chunks & Embeddings via LLM) │ │ 2. Data Cloud Retriever │ └──────────────────────────┬─────────────────────────────┘ │ ▼ Context Packaged ┌────────────────────────────────────────────────────────┐ │ EINSTEIN TRUST LAYER / AI APP │ │ 3. Prompt Template Builder (Merges Context + Prompt) │ └──────────────────────────┬─────────────────────────────┘ │ Grounded Prompt sent to LLM ▼ ┌────────────────────────────────────────────────────────┐ │ AGENTFORCE │ │ 4. Autonomous Service Agent (Executes Action/Response) │ └────────────────────────────────────────────────────────┘
  1. Ingestion & Embedding Layer: Unstructured data is ingested via Data Streams into Data Cloud, broken into pieces via chunking configurations, and processed by an embedding model.
  2. Indexing & Retrieval Layer: A Search Index stores the mathematical vectors. A dedicated Data Cloud Retriever fetches the matching document chunks when queries fire.
  3. Grounding Layer: The Einstein Prompt Template Builder injects retrieved data context into the system instructions while leveraging the Einstein Trust Layer for masking.
  4. Execution Layer: Agentforce evaluates the user intent, calls the prompt action, and responds cleanly to the end user.

4. Implementation Steps (5-Minute Summary)

The technical deployment breaks down into four sequential execution phases:

Phase 1 Configure Search Index in Data Cloud

Create a Data Stream to pull Case data into Data Cloud, mapping the generated Case_Home Data Lake Object (DLO) straight to your Case Data Model Object (DMO).

  • Create a Vector Search Index targeting fields like Subject and Description.
  • Set the Search Type to Hybrid Search.
  • Verify the execution states until status updates to Ready. This produces your chunking mechanisms (Case_chunk_dlmCopy) and structural index paths (Case_index_dlmCopy).
Phase 2 Build the Data Cloud Retriever

Register a custom retriever inside AI Models to map how the engine calls your data index. While ensemble retrievers handle multiple distinct configurations, an individual retriever is perfect here.

Configure the specific payload fields to map under Fields to Return:

  • Subject: DirectAttributes > Case > Subject
  • Description: DirectAttributes > Case > Description
  • Chunk: RelatedAttributes > Case chunk > Chunk
Phase 3 Draft the Grounded Prompt Template

Launch the Prompt Builder and construct a new template using the Knowledge Answers type.

### INSTRUCTIONS
1. Analyze the query: Carefully read and understand the user's question or issue from the QUESTION section.
2. Search CASE: Review the provided company CASE to find relevant information.
3. Evaluate information: Determine if the available information in the CASE section is sufficient to answer the QUESTION.
4. Formulate response: To generate a reply <generated_response> to the user, you must follow these rules:
   a. Find the article-chunk(s) that is most relevant and VERBATIM extract the ID to set the <source_id> field. If missing, set to NONE.
   b. Use the relevant article-chunk to generate the response that exactly answers the user's question.
   c. If it cannot be answered, set <source_id> to NONE and <generated_response> to "Sorry, I can't find an answer based on the available articles."
5. Refine and deliver: Ensure your response is polite, professional, and concise.
6. Review response: Strictly stick to the provided CASE only to formulate your answer.
###
CASE:
[Insert Retriever Token Here]
###
QUESTION:
{!$Input:Query}
###
Response:

Replace the retriever marker by clicking Insert Resource, locate your Case Retriever, configure your Search Text parameter to point to Query, set results limits to 5, then Save and Activate.

Phase 4 Deploy and Wire Up Agentforce

Navigate to Agentforce Studio to bundle the prompt template execution directly into your agent runtime architecture:

  1. Create a New Agent Action referencing your active Prompt Template.
  2. Supply clean routing descriptions so the agent understands its operational domain (e.g., "Answer questions that customers have about product issues using provided customer cases...").
  3. Configure Inputs: Set Query to Collect data from user and toggle Citation Mode to suppress default citation blocks. Set Outputs to Show in conversation.
  4. Initialize your Toaster Service Agent. Ensure permissions are applied via the Agentforce Service Agent Secure Base assignment.
  5. Build a new Subagent (Topic), write instructions, assign your custom action, and click Preview to test live grounding loops.

5. Metadata & Git Repository Blueprint

To establish clean CI/CD migration paths across Orgs, manage your configuration tracking via this precise package.xml manifest framework:

<?xml version="1.0" encoding="UTF-8"?>
<Package xmlns="http://soap.sforce.com/2006/04/metadata">
    <!-- 1. DATA CLOUD EMBEDDING & SEARCH LAYER -->
    <types>
        <members>*</members>
        <name>DataObjectSearchIndexConf</name>
    </types>

    <!-- 2. AI GENERATION & PROMPT LAYER -->
    <types>
        <members>*</members>
        <name>GenAiPromptTemplate</name>
    </types>

    <!-- 3. AGENTFORCE ORCHESTRATION LAYER -->
    <types>
        <members>*</members>
        <name>GenAiPlannerBundle</name>
    </types>
    <types>
        <members>*</members>
        <name>GenAiPlugin</name>
    </types>
    <types>
        <members>*</members>
        <name>GenAiFunction</name>
    </types>

    <version>65.0</version>
</Package>

Component Metadata Definitions

Metadata Type Architectural Governance Target
DataObjectSearchIndexConf Manages data chunk parameters, tokens, and embedding model association configurations.
GenAiPromptTemplate Stores engineering expressions, system directions, and dynamic retriever merge fields.
GenAiPlannerBundle Acts as the core container controlling intent-routing models and agent sub-properties.
GenAiPlugin Isolates global subagent topic maps and specialized contextual activation conditions.
GenAiFunction Encapsulates individual invocable calls or action rules attached to agents.
⚠️ Critical Manual Deployment Dependencies
  • Data Kits First: The index configuration relies on existing schemas. Deploy Data Streams, Mappings, and DMO structures inside a Data Cloud DevOps Data Kit before migrating the metadata package.
  • Dataspaces Setup: Custom Dataspaces are evaluated at execution time and do not auto-provision. Ensure the matching target Org dataspace names match your source environment exactly.
  • Manual Re-index: Pushing the metadata structures only copies the configuration template rules. You must navigate to Data Cloud Setup in the target environment and manually run the Initial Index Construction routine to build the local vector records.
