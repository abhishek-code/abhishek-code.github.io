As a Salesforce consultant, adding the Einstein 1 Platform's predictive capabilities to your toolbelt is a major win. This specific badge focuses on bridging the gap between raw data in Data Cloud and operationalizing AI for sales teams. Here is a high-level overview of what the badge accomplishes, its architectural footprint, and a quick 5-minute summary of the implementation steps you can use to explain it to a client or stakeholder. 1. What the Badge Does The Predictive Outputs from Model Builder module teaches you how to build a custom AI machine learning model to predict the likelihood of a lead converting. Instead of leaving that prediction locked inside Data Cloud, it shows you how to bring it directly into the core CRM, reason about it using generative AI, and display it beautifully on the Lead record page for sales reps. 2. Solution Description The Problem: Sales reps waste time chasing low-quality leads because they lack insight into which leads are mathematically most likely to convert based on historical data. The Solution: A predictive Lead Conversion model built in Einstein Studio (Model Builder) that scores leads using unified Data Cloud data. The score is pulled into a prompt template via Prompt Builder where generative AI creates a quick summary of why the lead is scored that way, and the entire payload is surfaced dynamically on the lightning page via Flow Builder. 3. High-Level Architecture The solution relies on four key components of the Salesforce ecosystem working seamlessly together: [ Data Cloud ] ----------> [ Einstein Studio / Model Builder ] (Unified Data Profiles) (Predictive ML Model: Lead Conversion Score) | v [ Lightning Record Page ] <--- [ Screen Flow ] <--- [ Prompt Builder ] (End User UI Component) (Invokes Prompt) (Grounds data & structures prompt) Data Cloud: Acts as the data foundation, housing the historical lead data needed to train the model. Einstein Studio (Model Builder): The predictive engine where the Machine Learning (ML) model is created, configured, and trained to output a "Predicted Conversion" score. Prompt Builder: The generative layer. It takes the predictive score, pairs it with CRM lead data (grounding), and instructs an LLM to generate a natural-language reason behind the score. Flow Builder (Screen Flow): The orchestration layer. It runs on the Lead page, triggers the prompt template, and serves the response directly to the user interface. 4. Implementation Steps (5-Minute Summary) how to build this in five minutes, frame it in these four sequential stages: Step 1: Train the Predictive Model in Einstein Studio (~1 min) Navigate to Einstein Studio (Data Cloud) and create a new model using Model Builder. Choose Predictive Model (typically using the Autopilot or binary classification route). Select your training dataset (historical Data Cloud data) and define the target outcome variable (e.g., IsConverted = True). Train the model to generate the Predicted Conversion score. Step 2: Connect the Prediction to the Core CRM (~1 min) Once trained, activate the model in Einstein Studio. Ensure the model's outputs are accessible to core Salesforce objects so they can be queried by automation tools. Step 3: Author the GenAI Prompt Template (~1.5 min) Open Prompt Builder and create a new Field Generation or Flex Prompt Template. Set the target object as the Lead. Insert the predictive model's score as a dynamic resource merge field (grounding the prompt). Write the system instructions: "You are an AI sales assistant. Take the Lead's prediction score of {!Model_Score} and summarize the key reasons why this lead is likely or unlikely to convert in 2 sentences." Step 4: Build the UI Screen Flow & Deploy (~1.5 min) Create a new Screen Flow that triggers automatically when a user views a Lead record. Add an Action element to invoke your newly created Prompt Template, passing the current record's ID into the prompt. Add a Screen element and place a Display Text component on it to show the rich-text output generated by the prompt. Save, activate, and drag the Screen Flow onto your Lead Lightning Record Page using the Lightning App Builder. Consultant Takeaway: The true beauty of this architecture is that it is entirely low-code. You are combining traditional predictive AI (scoring) with modern generative AI (text summarization) without writing a single line of Apex or Python. Meta-data for Git Repository To move the solution built in sandbox through a CI/CD pipeline and extract it to a Git repository, you need to grab the metadata components for the core CRM, the AI/Prompt layers, and the Data Cloud configurations. Use at least API Version 60.0 or higher in your sfdx-project.json or package.xml manifest, as the newer generative AI metadata types are not supported in older versions. The precise metadata types you can extract using the Salesforce CLI (sf project retrieve) are organized by architectural layer below: 1. The Generative AI & Predictive Layer These are the core components built using Prompt Builder and Einstein Studio: GenAiPromptTemplate: This contains your prompt template instructions, the grounding configurations, and target object associations. File extension: .genAiPromptTemplate (stored in the genAiPromptTemplates/ folder). GenAiPromptTemplateActv: Captures whether the prompt template version is actively turned on or hidden from the org. File extension: .genAiPromptTemplateActivation (stored in the genAiPromptTemplateActivations/ folder). DiscoveryGoal: If your Model Builder model was deployed as a custom prediction definition in core CRM, it maps to this type. It stores the metadata associated with the model's deployment, target variables, and field mappings. File extension: .discovery (stored in the discovery/ folder). 2. The Orchestration & UI Layer (Core CRM) These elements handle running the automation and displaying the outcome to the sales team: Flow: The Screen Flow that invokes the generative AI action and captures the text output. File extension: .flow (stored in the flows/ folder). FlexiPage: The Lightning Record Page layout for the Lead object where you dragged and dropped the Screen Flow component. File extension: .flexipage (stored in the flexipages/ folder). 3. The Data Cloud Foundation Layer (Data 360) Because this prediction draws data from Data Cloud, you must track the underlying schema and mappings. In enterprise environments, these are packaged together in a Data Kit (DataPackageKitDefinition), but the singular components include: DataStreamDefinition: Represents the ingestion settings and source mapping (e.g., pulling lead data into the platform). DataSrcDataModelFieldMap: The critical mapping metadata that connects your Data Lake Objects (DLOs) to your unified Data Model Objects (DMOs). BatchDataTransform (or DataTransform): The metadata tracking how data was cleaned up, joined, or transformed before being fed to the machine learning model.
